Eight hands-on projects that grow with the course. Each folder has its own README with instructions,
runnable code and (from Project 2 on) tests.

| # | Project | Do it | Concepts |
|---|---|---|---|
| 1 | [Student Information System](01-student-information-system/README.md) | After Day 28 | variables, input, conditions, lists, dictionaries |
| 2 | [Python Calculator](02-python-calculator/README.md) | After Day 53 | functions, operators, conditions, exception handling, pytest |
| 3 | [Log File Analyzer](03-log-file-analyzer/README.md) | After Day 55 / 73 | file handling, strings, loops, dictionaries, exceptions, regex, argparse |
| 4 | [Linux System Health Checker](04-linux-system-health-checker/README.md) | After Day 62 / 75 | os, subprocess, logging, file handling, /proc |

| 6 | [CSV Data Analysis](06-csv-data-analysis/README.md) | After Day 90 | NumPy, pandas, cleaning, grouping, charts, Markdown report |
| 7 | [Machine Learning Prediction Project](07-ml-prediction-project/README.md) | After Day 96 | pandas, scikit-learn, cross-validation, evaluation, serialization |
| 8 | [End-to-End MLOps Deployment](08-end-to-end-mlops-deployment/README.md) | After Day 100 | pandas, scikit-learn, FastAPI, Docker, API testing, CI/CD, Kubernetes |

## How to work on a project
1. Read the project README and try to build it **yourself** first, using the lessons as reference.
2. Compare with the provided implementation — it is one good solution, not the only one.
3. Run the tests (`pytest -q`) and try the "Extend it" ideas.
4. Push your version to your own GitHub profile — these make great portfolio pieces.
